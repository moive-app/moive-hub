# 로그인 · 회원가입 정책 및 예외 처리

> 앱 실행부터 로그인, 회원가입, 약관 동의, 가입 완료까지의 사용자 플로우와 예외 처리 정책을 정의한다.
> 
> 
> 본 문서는 기획/디자인/FE/BE가 동일한 인증 정책을 기준으로 개발하기 위한 문서이다.
> 

---

## 1. 인증 정책 개요

소셜 로그인을 기반으로 사용자를 인증한다.

### 로그인 수단

- **카카오 로그인:** 기본 로그인 수단
- **구글 로그인:** 개발 일정에 여유가 있을 경우 추가 구현 (후순위)

현재 와이어프레임에는 카카오 로그인과 구글 로그인을 배치한다.

단, **MVP에서 반드시 구현해야 하는 로그인 수단은 카카오 로그인**이다.

구글 로그인이 구현되는 경우에도 카카오 로그인과 동일한 신규/기존 회원 분기 및 약관 동의 플로우를 적용한다.

---

## 2. 핵심 인증 원칙

1. 별도의 아이디/비밀번호 회원가입은 제공하지 않는다.
2. 소셜 로그인이 로그인 및 회원가입의 진입점 역할을 한다.
3. 카카오 인증 성공 후 MOIVE 회원 여부를 확인한다.
4. 기존 회원은 로그인 후 홈으로 이동한다.
5. 신규 회원은 약관 동의 후 회원가입을 진행한다.
6. 회원가입 API가 성공하면 회원가입과 동시에 자동 로그인 처리한다.
7. 가입 완료 화면은 신규 회원에게만 노출한다.
8. 로그인 상태가 유지되는 사용자는 앱 실행 시 스플래시 후 바로 홈으로 이동한다.
9. 온보딩은 최초 이용자에게만 노출한다.
10. 로그인/회원가입 과정의 예외 상황은 별도 에러 화면 없이 토스트로 처리한다.
11. 회원가입 처리 중에는 현재 화면에서 로딩 상태를 표시한다.
12. 카카오 인증 완료 상태와 MOIVE 회원가입 완료 상태를 별도로 관리한다.

---

## 3. 전체 사용자 플로우

### 3.1 비로그인 사용자 → 신규 회원

처음 앱을 실행했거나 현재 로그인 상태가 없는 사용자는 비로그인 상태로 진입한다.

```
앱 실행
 ↓
스플래시
 ↓
인증 상태 확인
 ↓
인증 정보 없음
 ↓
온보딩
 ↓
로그인
 ↓
카카오 로그인
 ↓
카카오 인증 성공
 ↓
MOIVE 회원 여부 확인
 ↓
신규 회원
 ↓
약관 동의
 ↓
회원가입 API
 ↓
자동 로그인
 ↓
가입 완료 화면
 ↓
MOIVE 시작하기
 ↓
홈
```

비로그인 상태에서는 아직 회원 여부를 확인할 수 없으므로, 카카오 인증 완료 후 회원 여부를 확인하여 신규 회원과 기존 회원을 분기한다.

---

### 3.2 비로그인 사용자 → 기존 회원

현재 로그인 상태가 없더라도 카카오 로그인을 통해 기존 회원임이 확인되면 별도의 회원가입 절차 없이 홈으로 이동한다.

```
앱 실행
 ↓
스플래시
 ↓
인증 상태 확인
 ↓
인증 정보 없음
 ↓
온보딩
 ↓
로그인
 ↓
카카오 로그인
 ↓
카카오 인증 성공
 ↓
MOIVE 회원 여부 확인
 ↓
기존 회원
 ↓
로그인 완료
 ↓
홈
```

기존 회원에게는 약관 동의 및 가입 완료 화면을 다시 노출하지 않는다.

---

### 3.3 기존 로그인 회원

유효한 Refresh Token을 보유하고 있어 로그인 상태가 유지되는 사용자는 별도의 로그인 및 온보딩 절차를 거치지 않는다.

```
앱 실행
 ↓
스플래시
 ↓
로그인 상태 확인
 ↓
Refresh Token 유효
 ↓
홈
```

로그인 상태가 유지되는 기존 회원은 스플래시 이후 바로 홈으로 이동한다.

---

### 3.4 가입 미완료 사용자

카카오 인증은 완료했지만 회원가입 API가 아직 성공하지 않은 사용자는 가입 미완료 상태로 판단한다.

```
앱 실행
 ↓
스플래시
 ↓
인증 상태 확인
 ↓
카카오 인증 유효
 ↓
회원가입 미완료
 ↓
약관 동의
```

#### 앱 종료 후 재진입

약관 동의 중 앱이 종료된 경우에도 카카오 인증 상태가 유효하다면 다시 약관 동의 화면으로 이동한다.

```
약관 동의
 ↓
앱 종료
 ↓
앱 재실행
 ↓
스플래시
 ↓
인증 상태 확인
 ↓
카카오 인증 유효 + 회원가입 미완료
 ↓
약관 동의
```

카카오 인증 자체가 만료된 경우에는:

```
스플래시
 ↓
인증 상태 확인
 ↓
인증 만료
 ↓
로그인
 ↓
다시 카카오 로그인
```

으로 진행한다.

---

### 3.5 가입 완료 회원의 재진입

회원가입 API가 성공한 순간 회원가입이 완료된 것으로 간주하며, 자동 로그인 상태가 생성된다.

```
회원가입 API 성공
 ↓
자동 로그인
 ↓
가입 완료 화면
 ↓
MOIVE 시작하기
 ↓
홈
```

가입 완료 화면을 보던 중 앱을 종료하더라도 회원가입은 취소되지 않는다.

다음 앱 실행 시:

```
앱 실행
 ↓
스플래시
 ↓
인증 상태 확인
 ↓
Refresh Token 유효
 ↓
홈
```

가입 완료 화면을 다시 노출하지 않는다.

## 4. 스플래시

### 목적

- MOIVE 브랜드 노출
- 앱 초기 로딩
- 로그인 상태 확인
- 최초 사용자 / 기존 사용자 / 가입 미완료 사용자 분기

### 기본 정책

앱 실행 시 스플래시를 노출하는 동안 인증 상태를 확인한다.

인증 상태 확인을 위한 별도의 화면은 제공하지 않으며, **인증 상태 확인이 완료될 때까지 스플래시 화면을 유지한다.**

인증 상태 확인 결과에 따라 다음 화면으로 분기한다.

### 인증 상태별 분기

| 인증 상태 | 이동 |
| --- | --- |
| 로그인 상태 유효 | 홈 |
| 인증 정보 없음 | 온보딩 |
| Refresh Token 유효 | 홈 |
| Refresh Token 만료 | 재인증 시도 |
| Refresh Token 갱신 성공 | 홈 |
| Refresh Token 갱신 실패 | 로그인 |
| 카카오 인증 완료 + 회원가입 미완료 | 약관 동의 |
| 인증 상태 확인 중 | 스플래시 유지 |
| 인증 서버 통신 실패 | 로그인 상태에 따라 처리 |

## 5. 온보딩

### 노출 대상

MOIVE를 최초 이용하는 사용자에게만 노출한다.

기존 회원에게는 반복해서 노출하지 않는다.

### 구성

현재 와이어프레임에 구성된 온보딩 화면을 따른다.

### 건너뛰기

온보딩에는 **건너뛰기 버튼을 제공하지 않는다.**

사용자는 온보딩을 순서대로 확인한 후 마지막 화면에서 로그인으로 이동한다.

### Android 뒤로가기

온보딩에는 이전 화면이 존재하지 않는다.

따라서 Android 시스템 뒤로가기를 누르면:

> **앱 종료**
> 

로 처리한다.

온보딩 화면에서 별도의 종료 확인 팝업은 제공하지 않는다.

## 9. 회원 식별 기준

MOIVE 회원 여부는 **카카오 회원의 고유 식별 ID**를 기준으로 판단한다.

이메일을 회원의 고유 식별값으로 사용하지 않는다.

### 기본 구조

```
Kakao Member ID
        ↓
MOIVE User
```

카카오 이메일은 필요한 경우 사용자 정보로 활용할 수 있으나, 동일 사용자 여부를 판단하는 기준으로 사용하지 않는다.

> 정확한 API 필드명 및 DB 컬럼명은 BE 구현 시 확정한다.
>

## 10. 카카오 로그인 처리 중

카카오 로그인 요청 및 인증 처리 중에는 중복 요청을 방지한다.

### 처리

- 로그인 버튼 연속 클릭 방지
- 로그인 요청 중 버튼 비활성화
- 인증 완료 후 다음 단계로 이동
- 별도의 로그인 로딩 화면은 생성하지 않는다.

필요한 경우 버튼 내부에서 로그인 처리 상태를 표시한다.

---

## 11. 카카오 로그인 취소

사용자가 카카오 인증 화면에서 뒤로가기 또는 취소를 선택한 경우:

```
카카오 로그인
 ↓
사용자 취소
 ↓
로그인 화면
 ↓
토스트
```

#### 토스트

> 로그인이 취소되었어요.
> 

### 정책

- 로그인 실패로 처리하지 않는다.
- 회원가입 상태로 변경하지 않는다.
- 로그인 화면을 유지한다.
- 사용자가 다시 카카오 로그인을 시도할 수 있다.

---

## 12. 카카오 인증 성공 후 서버 통신 실패

카카오 인증 자체는 성공했지만 서버에서 회원 여부 확인에 실패하는 경우.

예:

```
카카오 인증 성공
 ↓
MOIVE 회원 조회
 ↓
서버 통신 실패
```

### 처리

```
로그인 실패 토스트
 ↓
로그인 화면 유지
 ↓
다시 카카오 로그인
```

#### 토스트

> 로그인을 완료하지 못했어요. 다시 시도해주세요.
> 

카카오 인증 성공 여부와 관계없이 MOIVE 서버에서 정상적인 인증/회원 확인이 완료되지 않으면 로그인 완료 상태로 처리하지 않는다.

---

## 13. 카카오 필수 사용자 정보 동의

가입에 필요한 카카오 사용자 정보가 필수 제공 항목인 경우 해당 정보가 확보되지 않으면 회원가입을 완료할 수 없다.

### 처리 원칙

```
카카오 로그인
 ↓
필수 정보 제공 동의 확인
 ↓
필수 정보 미동의/미제공
 ↓
회원가입 진행 불가
 ↓
다시 카카오 로그인
```

별도의 프로필 입력 화면을 추가하지 않는다.

필수 정보가 제공되지 않아 가입을 진행할 수 없는 경우 사용자가 다시 카카오 인증 및 필요한 정보 제공 동의를 진행하도록 한다.

> 실제 필수 정보 및 카카오 동의 항목은 BE/카카오 로그인 설정 기준으로 확인한다.

## 14. 로그인 실패

카카오 인증 또는 로그인 처리 중 오류가 발생한 경우 별도 에러 화면을 생성하지 않는다.

### 처리

- 로그인 화면 유지
- 토스트 노출
- 다시 로그인 가능

#### 기본 토스트

> 로그인을 완료하지 못했어요. 다시 시도해주세요.
>

## 15. 네트워크 오류

로그인 또는 회원가입 과정에서 네트워크 연결 문제가 발생한 경우:

#### 토스트

> 네트워크 연결을 확인해주세요.
> 

### 처리

- 현재 화면 유지
- 입력/체크 상태 유지

## 19. 전체 동의


전체 동의 해제 시 모든 약관을 해제한다.

개별 약관을 변경한 경우 전체 동의 상태는 실제 개별 선택 상태와 일치시킨다.

예:

```
전체 동의 OFF

서비스 이용약관 ✓
개인정보 처리방침 ✓
마케팅 수신 동의 ✕
```

## 20. 필수 약관 미동의

서비스 이용약관과 개인정보 처리방침은 필수 약관이다.

두 약관에 모두 동의하지 않은 경우 회원가입을 진행할 수 없다.

### 다음 버튼

#### 필수 약관 미동의

```
☐ 서비스 이용약관 (필수)
☐ 개인정보 처리방침 (필수)

[다음] 비활성화
```

#### 필수 약관 동의

```
✓ 서비스 이용약관 (필수)
✓ 개인정보 처리방침 (필수)

[다음] 활성화
```

마케팅 수신 동의 여부는 회원가입 가능 여부에 영향을 주지 않는다.

## 21. 약관 상세

약관 항목의 `>`를 선택하면 해당 약관의 전문을 확인할 수 있다.

### 제공 페이지

- 서비스 이용약관
- 개인정보 처리방침
- 마케팅 수신 동의

### 상세 화면

약관 전문을 확인할 수 있다.  (별도의 `동의` 버튼을 제공하지 않음.)

사용자는 뒤로가기로 약관 동의 화면으로 돌아가고, 메인 화면에서 체크박스를 통해 동의한다.

다시 카카오 로그인을 진행하여 신규 회원 플로우를 시작할 수 있다.

## 23. 약관 동의 정보 저장

- 약관 버전

- 동의 일시

## 24. 회원가입 처리 중

약관 동의 후 `다음`을 선택하면 회원가입 API를 요청한다.

### 처리

- `다음` 버튼 중복 클릭 방지
- 버튼 비활성화
- **로딩 아이콘 표시**
- 회원가입 API 완료까지 현재 화면 유지
- 성공 시 가입 완료 화면으로 이동
- 실패 시 약관 화면 유지

별도의 회원가입 처리 중 화면은 생성하지 않는다.

## 27. 이미 가입된 계정이 신규 회원가입 요청을 보내는 경우

동일 카카오 회원 식별 ID가 이미 MOIVE DB에 존재하는데 회원가입 요청이 중복으로 들어온 경우:

**기존 회원으로 간주하고 로그인 처리한다.**

별도의:

> 이미 가입된 계정입니다.
> 

에러를 발생시키지 않는다.

즉, 동일 사용자의 중복 가입 요청은 가능한 경우 **멱등적으로 기존 회원 로그인 상태로 처리**한다.

## 28. 가입 중 앱 종료

다음 앱 실행 시 인증 상태를 확인한다.

#### 카카오 인증은 유효하지만 MOIVE 회원가입이 완료되지 않은 경우

즉, **인증 상태가 유효하면 약관 동의로 복귀하고, 인증 상태 자체가 유효하지 않으면 다시 카카오 로그인부터 진행한다.**

## 29. 회원가입 완료 기준

**회원가입 API 성공 = 회원가입 완료**

로 정의한다.

가입 완료 화면에 정상적으로 진입했는지 여부는 회원가입 완료 여부와 관계없다.

즉:

```
회원가입 API 성공
= 회원 생성 완료
= 인증 상태 생성
= 자동 로그인
= 회원가입 완료
```

## 30. 가입 완료 및 자동 로그인

```

 ↓
인증 정보 저장
 ↓
자동 로그인
 ↓
가입 완료 화면
```

사용자는 가입 완료 후 별도의 로그인 과정을 거치지 않는다.

## 40. 카카오 프로필 정보 변경 정책

카카오 로그인으로 최초 가입 시 카카오에서 제공받은 프로필 정보를 MOIVE의 초기 프로필 정보로 활용한다. 그러나 **가입 이후 MOIVE의 프로필 정보는 카카오 계정 정보와 독립적으로 관리한다.**

즉:

```
최초 가입
카카오 닉네임/프로필
 ↓
MOIVE 초기 프로필 생성
```

이후:

```
카카오 닉네임 변경
카카오 프로필 사진 변경
        ↓
MOIVE 프로필에는 자동 반영하지 않음
```

가입 이후 MOIVE 프로필은 MOIVE 내부에서 관리한다.

프로필 수정 기능은 마이페이지에서 별도로 정의한다.

## 41. 탈퇴 후 동일 카카오 계정 재가입

회원 탈퇴 후 동일한 카카오 계정으로 다시 로그인하는 경우 **완전히 신규 회원으로 처리한다.**

```
기존 MOIVE 회원
 ↓
회원 탈퇴
 ↓
동일 카카오 계정으로 로그인
 ↓
신규 회원
 ↓
약관 동의
 ↓
신규 회원가입
 ↓
가입 완료
```

기존 회원의 로그인 상태나 계정을 복구하지 않는다.

기존 데이터 복구 정책은 회원 탈퇴 정책에서 별도로 정의한다.

## 47. 핵심 정책 요약

> **MOIVE는 카카오 인증을 통해 사용자를 식별하고, 신규 사용자는 필수 약관 동의 후 회원가입을 진행한다.**
> 

> **회원가입 API가 성공한 순간 회원가입과 자동 로그인을 완료한 것으로 간주하며, 이후 가입 완료 화면을 보여준 뒤 사용자가 MOIVE 시작하기를 선택하면 홈으로 이동한다.**
> 

> **기존 로그인 사용자는 Refresh Token이 유효한 동안 로그인 상태를 유지하며, 앱 실행 시 스플래시 후 바로 홈으로 이동한다.**
> 

> **카카오 인증과 MOIVE 회원가입은 별개의 상태로 관리한다. 카카오 인증은 완료됐지만 회원가입이 완료되지 않은 사용자가 앱을 종료하면, 다음 실행 시 인증이 유효한 경우 약관 동의 화면으로 돌아간다. 인증 자체가 만료된 경우에는 다시 카카오 로그인부터 진행한다.**
> 

> **로그인/회원가입 과정에서 발생하는 취소, 실패, 네트워크 오류, 서버 오류 등은 별도의 에러 화면을 만들지 않고 토스트로 처리한다. 회원가입 API 처리 중에는 현재 화면에서 로딩 아이콘을 표시하고 중복 요청을 방지한다.**
> 

> **탈퇴 후 동일 카카오 계정으로 다시 로그인하는 경우 기존 계정을 복구하지 않고 완전히 신규 회원으로 처리한다.**
> 

> **가입 이후 MOIVE 프로필은 카카오 계정 정보와 독립적으로 관리하며, 이후 카카오에서 프로필 정보가 변경되더라도 MOIVE 프로필에는 자동 반영하지 않는다.**
>
