# 디자인 문서

이 폴더는 MOIVE의 디자인 원칙, 디자인 시스템, UX 리서치와 화면 단위의 협업 현황을 관리합니다.
Figma는 시각 산출물의 원본이며, 이 폴더는 화면이 기획·디자인·개발·QA를 거치는 과정을 한눈에 확인할 수 있게 하는 기준 인덱스입니다.

## 화면 현황 관리

[screens.md](screens.md)는 모든 화면의 단일 현황표입니다. 각 행에는 다음 정보를 유지합니다.

- 화면명과 Figma 원본 링크
- 관련 Discord Forum/Thread 논의 링크
- 디자인 상태
- 상세 기획 Notion 링크와 상세 기획 상태
- 개발 상태와 QA 상태
- 담당자, 마지막 업데이트, 관련 문서

화면의 복잡한 요구사항, 결정 배경, 상태 변경 이력은 [화면 상세 템플릿](templates/screen.md)을 사용해 별도 문서로 관리할 수 있습니다. 화면 상세 문서는 `docs/design/screens/`에 화면명 기준의 kebab-case 파일명으로 만들고, `screens.md`의 관련 문서 열에서 연결합니다.

## Discord 논의 연결

Discord는 기능별 논의의 원본입니다. 화면과 관련된 Forum Channel 및 Thread는 화면 관리표와 화면 상세 문서에 연결해, 질문·의견·결정 과정의 맥락을 추적할 수 있게 합니다.

Discord의 의견은 미확정일 수 있으므로, 화면의 확정 요구사항·정책으로 해석하지 않습니다. 확정된 상세 기획과 정책은 Notion 공식 문서를 우선하고, 중요한 결정은 `docs/decisions/`에 Discord와 Notion 링크를 함께 남깁니다.

## 상태값 기준

각 단계의 상태는 독립적으로 관리합니다. 예를 들어 디자인이 완료되어도 상세 기획, 개발, QA는 진행 중일 수 있습니다.

| 구분 | 권장 상태값 | 의미 |
| --- | --- | --- |
| 디자인 | `미정`, `진행 예정`, `진행 중`, `검토 중`, `완료`, `보류` | Figma 디자인 작업과 검토 상태 |
| 상세 기획 | `미정`, `진행 예정`, `작성 중`, `검토 중`, `확정`, `보류` | 화면 요구사항·정책의 정의 상태 |
| 개발 | `미정`, `대기`, `진행 중`, `리뷰 중`, `완료`, `보류` | 구현과 코드 리뷰 상태 |
| QA | `미정`, `대기`, `진행 중`, `수정 필요`, `통과`, `보류` | 검증 결과와 후속 조치 상태 |

새 상태값이 필요하면 임의로 추가하기보다 이 문서에 의미를 먼저 정의합니다.

## 갱신 규칙

1. 화면이 새로 정의되면 `screens.md`에 추가합니다.
2. 각 직군의 상태가 변경되면 해당 열과 `마지막 업데이트`를 같은 변경에서 갱신합니다.
3. 링크가 아직 없으면 빈 URL을 만들지 말고 `미연결`로 표시합니다.
4. 화면을 분리·통합·폐기하면 기존 행을 삭제하지 말고 상태와 대체 화면 또는 관련 결정 문서를 기록합니다.
5. 상태만으로 설명되지 않는 변경은 화면 상세 문서나 의사결정 기록으로 연결합니다.
6. Discord 링크가 여러 개인 경우 `Forum: [링크]`와 `Threads: [링크 1], [링크 2]`처럼 구분해 한 셀에 기록합니다.
